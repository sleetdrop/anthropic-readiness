## Material rulings and evidence

- Only server-verified assertion references carry escaped annotation metadata.
  FAIL is required for fault markers. Explicit pointers and a closed list of
  display associations cover recorded model/stop-field/usage failures and repeated
  message starts. Unknown compound failures retain no guessed node. These are
  reading associations over existing outcomes, not new assertions or validation.
- Missing fields mark an existing parent; primitive traversal/invalid pointers
  cannot be presented as missing-object proof. Unparseable bodies, non-failing
  assertions, out-of-prefix events and truncated bodies do not get fabricated
  markers. Only complete loaded event records can support event annotation.
- The full frame is readable as a foldable projection, initially bounded to 500
  rows. Known late targets get an explicit partial reading window; full source
  remains available. Depth is capped at 64 and labeled; this is not source truncation.
- Popover text comes from the existing assertion/verified diagnostic observation.
  Where no expected text was recorded, the UI states that limitation. JSON and
  other untrusted strings use text nodes/escaped template attributes only.
- Initial fast run failed because the new HTML include was absent from the exact
  template inventory; it was explicitly added, retaining closed inventory checks.
- Browser failures were diagnosed, retained and corrected: full-page screenshots
  triggered resize-based dismissal (confirmed visible before/hidden after capture),
  so viewport screenshots now assert the popup remains open. A trial pointer-state
  workaround was removed. Native downloads bypass a display-only route override;
  download equality is now checked against independently fetched original bytes,
  not the synthetic display transport. No product expectation was weakened.
- Two acceptance command errors (wrong file name and then the pytest executable's
  import path) were retained as unrun/errors, not PASS. Correct python -m pytest
  invocation passed all 17 actual backend/package tests. Fast/browser tests were
  likewise rerun on final runtime source. The later icon README clarification is
  non-runtime and receives a final repeated fast check before commit/build.
